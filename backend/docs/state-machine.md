# State Machine

La maquina de estados es unica, pero se valida por `order.type`.

## Estados compartidos

- `CREATED`
- `VALIDATED`
- `ENERGY_ESTIMATION_REQUESTED`
- `ENERGY_ESTIMATED`
- `ENERGY_REQUESTED`
- `ENERGY_CONFIRMED`
- `READY_FOR_PAYOUT`
- `COMPLETED`
- `CANCELED`
- `ERROR_RETRYABLE`
- `ERROR_MANUAL_REVIEW`

## Estados propios de SELL

- `ADDRESS_ASSIGNED`
- `WAITING_DEPOSIT`
- `DEPOSIT_DETECTED`
- `FORWARD_REQUESTED`
- `FORWARD_ACCEPTED`
- `SWEEP_CONFIRMED`
- `EXPIRED`
- `LATE_DEPOSIT`

## Estados propios de BUY

- `SEND_REQUESTED`
- `SEND_ACCEPTED`
- `SEND_BROADCASTED`
- `DELIVERY_CONFIRMED`

## Transiciones SELL

- `CREATED -> ADDRESS_ASSIGNED`
- `ADDRESS_ASSIGNED -> WAITING_DEPOSIT`
- `WAITING_DEPOSIT -> DEPOSIT_DETECTED | CANCELED | EXPIRED | ERROR_MANUAL_REVIEW`
- `DEPOSIT_DETECTED -> ENERGY_ESTIMATION_REQUESTED | ENERGY_REQUESTED | ERROR_MANUAL_REVIEW`
- `ENERGY_ESTIMATION_REQUESTED -> ENERGY_ESTIMATED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_ESTIMATED -> ENERGY_REQUESTED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_REQUESTED -> ENERGY_CONFIRMED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_CONFIRMED -> FORWARD_REQUESTED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `FORWARD_REQUESTED -> FORWARD_ACCEPTED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `FORWARD_ACCEPTED -> SWEEP_CONFIRMED | READY_FOR_PAYOUT | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `SWEEP_CONFIRMED -> READY_FOR_PAYOUT | COMPLETED | ERROR_MANUAL_REVIEW`
- `READY_FOR_PAYOUT -> COMPLETED | ERROR_MANUAL_REVIEW`
- `EXPIRED -> LATE_DEPOSIT`
- `CANCELED -> LATE_DEPOSIT`
- `ERROR_RETRYABLE -> ENERGY_ESTIMATION_REQUESTED | ENERGY_REQUESTED | FORWARD_REQUESTED | ERROR_MANUAL_REVIEW`
- `ERROR_MANUAL_REVIEW -> ERROR_RETRYABLE`

## Transiciones BUY

- `CREATED -> VALIDATED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `VALIDATED -> ENERGY_ESTIMATION_REQUESTED | ENERGY_REQUESTED | ENERGY_CONFIRMED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_ESTIMATION_REQUESTED -> ENERGY_ESTIMATED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_ESTIMATED -> ENERGY_REQUESTED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_REQUESTED -> ENERGY_CONFIRMED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `ENERGY_CONFIRMED -> SEND_REQUESTED | CANCELED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `SEND_REQUESTED -> SEND_ACCEPTED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `SEND_ACCEPTED -> SEND_BROADCASTED | DELIVERY_CONFIRMED | READY_FOR_PAYOUT | COMPLETED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `SEND_BROADCASTED -> DELIVERY_CONFIRMED | READY_FOR_PAYOUT | COMPLETED | ERROR_RETRYABLE | ERROR_MANUAL_REVIEW`
- `DELIVERY_CONFIRMED -> READY_FOR_PAYOUT | COMPLETED | ERROR_MANUAL_REVIEW`
- `READY_FOR_PAYOUT -> COMPLETED | ERROR_MANUAL_REVIEW`
- `ERROR_RETRYABLE -> ENERGY_ESTIMATION_REQUESTED | ENERGY_REQUESTED | SEND_REQUESTED | CANCELED | ERROR_MANUAL_REVIEW`
- `ERROR_MANUAL_REVIEW -> ERROR_RETRYABLE`

## Eventos que disparan transiciones

### SELL

- Creacion de orden:
  - `CREATED -> ADDRESS_ASSIGNED`
  - `ADDRESS_ASSIGNED -> WAITING_DEPOSIT`
- Webhook deposito valido:
  - `WAITING_DEPOSIT -> DEPOSIT_DETECTED`
- Solicitud de energia:
  - `DEPOSIT_DETECTED | ENERGY_ESTIMATED -> ENERGY_REQUESTED`
- Callback iTRX firmado:
  - `ENERGY_REQUESTED -> ENERGY_CONFIRMED`
- Solicitud de forward:
  - `ENERGY_CONFIRMED -> FORWARD_REQUESTED`
  - `FORWARD_REQUESTED -> FORWARD_ACCEPTED`
- Webhook sweep confirmado:
  - `FORWARD_ACCEPTED -> SWEEP_CONFIRMED`
  - `SWEEP_CONFIRMED -> READY_FOR_PAYOUT`
- Confirmacion de payout desde CAS:
  - `READY_FOR_PAYOUT -> COMPLETED`
- Expiracion:
  - `WAITING_DEPOSIT -> EXPIRED`
- Deposito tardio:
  - `EXPIRED | CANCELED -> LATE_DEPOSIT`

### BUY

- Creacion de orden:
  - `CREATED`
- Validacion y preparacion de energia:
  - `CREATED -> VALIDATED`
- Solicitud de energia:
  - `VALIDATED | ENERGY_ESTIMATED -> ENERGY_REQUESTED`
- Reutilizacion de energia vigente:
  - `VALIDATED -> ENERGY_CONFIRMED`
- Callback iTRX firmado:
  - `ENERGY_REQUESTED -> ENERGY_CONFIRMED`
- Solicitud de send:
  - `ENERGY_CONFIRMED -> SEND_REQUESTED`
  - `SEND_REQUESTED -> SEND_ACCEPTED`
- Webhook de envio:
  - `SEND_ACCEPTED -> SEND_BROADCASTED`
  - `SEND_BROADCASTED -> DELIVERY_CONFIRMED`
  - `DELIVERY_CONFIRMED -> COMPLETED`

## Acciones laterales

- `WAITING_DEPOSIT`
  - se encola `EXPIRE_ORDER`
- `DEPOSIT_DETECTED`
  - se persiste `cryptoAmountReceived`
  - se encola `REQUEST_ENERGY`
- `VALIDATED`
  - BUY queda listo para pedir energia del sender central
- `ENERGY_REQUESTED`
  - se crea `energy_requests`
- `ENERGY_CONFIRMED`
  - SELL: se encola `REQUEST_FORWARD`
  - BUY: se encola `SEND_BUY`
- `FORWARD_REQUESTED`
  - se crea `forward_requests`
- `SEND_REQUESTED`
  - se crea `send_requests`
- `FORWARD_ACCEPTED`
  - se persiste `providerForwardRequestId`
- `SEND_ACCEPTED`
  - se persiste `providerSendRequestId`
- `SWEEP_CONFIRMED`
  - se persiste `providerForwardTxid`
- `READY_FOR_PAYOUT -> COMPLETED`
  - CAS confirma que el payout de efectivo ya fue realizado
  - se valida correlacion con `casTransactionId` y `terminalId`
  - se audita la transicion final del SELL
- `DELIVERY_CONFIRMED`
  - se persiste `providerSendTxid`
- `ERROR_MANUAL_REVIEW`
  - `manualReviewRequired=true`
- `ERROR_MANUAL_REVIEW -> ERROR_RETRYABLE`
  - solo por accion manual controlada desde el panel
  - exige rol suficiente, motivo y step-up auth

## Persistencia

Cada transicion se guarda en `order_state_transitions` con:

- `fromStatus`
- `toStatus`
- `reason`
- `actorType`
- `actorId`
- `metadata`
- `createdAt`
